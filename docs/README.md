# aloud. landing page

Static site for the public aloud. landing page. Hand-written; no build step.

Despite the name, this is the public site (the folder is called `docs/` from when GitHub Pages served it off the branch). Developer documentation lives in `dev-docs/` at the repo root.

## structure

```
docs/
  index.html      ← landing page content + structure
  privacy/        ← privacy policy (hand-written)
  terms/          ← terms of service (hand-written)
  delete-account/ ← how to delete an account + what it forfeits. Play requires a
                    public URL for this, reachable without installing the app.
  account/        ← redirect to the web app's Account page (/app/account). The
                    Android app names aloud.rest/account in plain text, so it
                    must keep resolving.
  app/            ← the built web app (Vite output, base '/app/'); talks to aloud cloud.
                    Generated by the UI build, not hand-edited here.
  404.html        ← SPA deep-link redirect for /app/* on GitHub Pages (pairs with app/index.html)
  css/style.css   ← brand tokens lifted from dev-docs/style.md
  js/download.js  ← fetches latest GitHub release at page load
  js/theme.js     ← light/dark toggle (persists choice for 4h, else follows OS)
  js/shots.js     ← screenshot carousel: owns the `#app-screenshot` src (shot × theme)
  js/faq.js       ← FAQ expand/collapse-all control
  js/hero.js, js/settle.js ← hero ripple replay, card settle-in entrance
  assets/
    aloud.png               ← icon
    aloud-share.png         ← 1200×630 social card (og:image)
    aloud-screen-{light,dark}.webp  ← setup screenshot
    aloud-session-{light,dark}.webp ← session screenshot
```

What has to stay in sync with the product when it changes (copy, FAQ,
`/privacy`, `/terms`, screenshots) is listed in
[pre-release-checklist.md](../dev-docs/pre-release-checklist.md) Part A.

## local preview

Any static server. From the repo root:

```bash
python3 -m http.server -d docs 8000
# then open http://localhost:8000
```

## download wiring

`js/download.js` calls `https://api.github.com/repos/akrusz/aloud/releases/latest`
on page load and rewrites the three download-card `href`s with the latest
release asset URLs. If the API fails (rate-limited, offline, etc.) it falls
back to `https://github.com/akrusz/aloud/releases/latest` for all three.

So the site never needs a redeploy when a new version ships: the release
workflow uploads the assets and the next page load picks them up.

## deployment

GitHub Pages, source = **"GitHub Actions"** (the older "deploy from a branch,
folder `/docs`" mode is retired). `.github/workflows/deploy-web.yml` uploads this
whole tree as the Pages artifact; `CNAME` carries the custom domain.

**Two clocks:** these marketing pages publish on every push to `main` that
touches `docs/`, while `app/` is built from the **latest published release** and
only moves when one is cut - so the hosted app stays in step with the server it
talks to. See [deploy.md](../dev-docs/deploy.md#release-deploys-one-tag-ships-everything).
