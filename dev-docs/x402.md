# x402 credit purchases (USDC on Base)

A third purchase channel alongside Stripe and IAP: pay for a credit pack with
USDC over the x402 HTTP-402 flow. **Built, flag-gated OFF.** Server and client
both landed; what remains is a live testnet round-trip and the mainnet ops work
below.

**Status**
- Server + client: done, tested, green.
- Verified: enabled+authed+unpaid → 402 advertising the right USDC amount /
  network / asset / payTo / EIP-712 domain. The mainnet path refuses loudly
  rather than half-settling.
- **Not** done: an end-to-end run on Base Sepolia with a funded test wallet, and
  Phase 3 (mainnet CDP auth, off-ramp, refunds, tax).

## Decisions locked (do not re-litigate)

- **Hand-rolled over `fetch`, NO SDK** (matches `billing/stripe.ts`). Built on
  `x402-hono` + `@coinbase/x402` first, then reverted: the server owns no
  cryptographic verification in either design - the payer's wallet signs, and the
  facilitator verifies + settles on-chain. `viem` was used only for address
  checksumming / payment decode / price math. The middleware cost ~108MB and
  ~500 transitive packages (`node_modules` 717M→104M after the revert) for a thin
  HTTP broker, with no crypto-risk delta. The hand-roll is ~200 lines + static
  constants (USDC addresses, EIP-712 domain, facilitator URLs) and zero new deps.
  See commit abdc65f.
- **Treasury: a dedicated self-custody Base wallet + CDP facilitator.** A NEW
  address, not `krusz.eth` / the tip-jar address - keep business revenue separate
  from personal tips for tax sanity. CDP is free on Base and runs KYT/OFAC
  screening, which covers the AML question. The address is an env var.
- **Scheme/asset/chain:** `exact` (EIP-3009 `transferWithAuthorization`), USDC,
  Base. Test on **Base Sepolia**, mirroring how Stripe shipped in test mode.
- **Flag-gated, OFF by default.**
- **No viem/web3 in the UI bundle** (+~14KB plain JS vs hundreds of KB for
  `x402-fetch`): the client talks to the injected EIP-1193 wallet directly.

## Config

```
X402_ENABLED=1
X402_PAY_TO_ADDRESS=0x…            # Base address
X402_NETWORK=base-sepolia          # or `base`
CDP_API_KEY_ID / CDP_API_KEY_SECRET  # mainnet settlement only; testnet is keyless
```

The channel is "configured" only when `X402_ENABLED` and `X402_PAY_TO_ADDRESS`
are both set; otherwise the route reports "not configured", exactly like Stripe
without a key. `/cloud/v1/me/packs` advertises `{ x402: { enabled, network } }`,
and the buy-credits modal shows its Card | USDC toggle off that. USDC is
self-only (no gift flow) and settles in place, with no redirect.

## Idempotency (applies to Stripe too)

Purchases dedupe at the store layer, so both channels inherit it: a partial
unique index on `ledger(reason) WHERE kind = 'purchase'` in `sqlite-store.ts`
`SCHEMA`, and `appendEntry` treats a constraint violation on a `purchase`-kind
entry as a no-op. Reason strings are the dedup key:

- Stripe: `purchase:${packId}:${stripeSessionId}`
- x402:   `purchase:${packId}:x402:${txHash}`

This also fixed a latent bug: the direct Stripe purchase path was not idempotent,
so a webhook retry could have double-credited. (The gift path was already safe
via `gifts.stripe_session_id UNIQUE`.)

## Remaining: mainnet ops (blocking go-live, not testnet)

- Real treasury address + CDP mainnet API keys.
- **Off-ramp:** USDC → USD (providers bill us in USD). Manual at first.
- **Refunds:** on-chain is final, so this needs a manual refund runbook.
- **Tax:** Stripe Tax does NOT cover x402. Sales-tax/VAT on x402 purchases is
  unresolved - **treat as a mainnet go-live blocker.**
- **EU/Apple:** if x402 is ever exposed *inside the iOS app* in the EU, Apple's
  Core Technology Commission may apply just as it does to `web_stripe` EU. The
  channel is web/agent-only today, so there's no Apple cut; if that changes, add
  an EU row to `commission.ts`'s `TABLE` mirroring `web_stripe.EU` first.
