# Bowl / bell candidates

Bowl and rin sounds for the app and promo video. `bowl-mid-medium` and
`rin-short` ship as `bowl.mp3` / `rin.mp3` in `ts/ui/public/audio/` (copy
the mp3 over after re-tuning). All are synthesized by `synth_bowls.py` in
this folder, so there's no licensing question. Re-tune there (partial tables, `CANDIDATES`) and re-run:

```bash
python3 -m venv <venv> && <venv>/bin/pip install numpy scipy
<venv>/bin/python synth_bowls.py            # all
<venv>/bin/python synth_bowls.py rin-short
```

| File | Length | Character | Use |
|------|--------|-----------|-----|
| `bowl-deep-long` | 10.0s | Deep Himalayan bowl (~164 Hz / E3), felt mallet, left to ring. Richer upper partials, two-stage decay, slow pitch/level drift, metal grain, bigger room. | Session start/end, video |
| `bowl-mid-medium` | 5.0s | Mid bowl (~311 Hz / D#4), medium mallet, damped from 3s. Clear and round. | Noting / general |
| `rin-short` | 2.0s | Small Japanese rin (~1046 Hz / C6), harder striker, damped quickly. | Noting |
| `rin-long` | 7.0s | Same rin, full ring with shimmer from the upper partials. | Start/end, video |

Formats:
- `.wav`: 48 kHz, 24-bit, stereo, peaks at -1 dBFS. For video. Gitignored;
  re-run the script to get them.
- `.mp3`: 44.1 kHz stereo 128k (like most of the app's sounds; old `bell.mp3`
  is 24 kHz, which would cut the rin's upper partials). Gained so the first
  0.7s (the strike) measures -20 LUFS, level with `card`/`poof`/`rattle`.
  The old `bell.mp3` sat at -40.7, part of why it read as weak.
- `spectrograms/*.png`: log-frequency spectrograms of the wavs (gitignored).

Source/license: all synthesized, generated by `synth_bowls.py` (inharmonic
partials at measured bowl ratios ~1 : 2.7 : 5.1 : 8.2 : 11.9, detuned pairs for
beating, soft mallet transient, synthetic room).
